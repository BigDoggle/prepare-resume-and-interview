# PDF 简历转 HTML/CSS 模板

## 目录

1. 原则
2. 取证
3. 重建
4. 内容与表现分离
5. 对照验收
6. 常见失败

## 一、原则

PDF 是视觉权威，文本提取结果只是内容参考。目标是重建可编辑结构，不是把 PDF 页面转成背景图片。用户同时提供 DOCX 时，可用 DOCX 辅助恢复语义和图片，但版式以 PDF 为准。

## 二、取证

必须使用 PDF 读取/渲染能力并逐页查看：

1. 记录页数、页面尺寸、旋转和元数据；
2. 以稳定 DPI 渲染每页 PNG；
3. 提取文本，识别区块、列表、链接和阅读顺序；
4. 提取字体名、字号分布、字重和颜色；
5. 提取图片的源尺寸和 PDF 边界；
6. 测量页边距、列宽、标题线、区块起点和关键基线；
7. 识别固定分页还是自动流式分页。

建立视觉 token：纸张、页边距、正文/标题字体、字号、行高、强调色、线宽、区块间距、照片尺寸与位置。

如果字体未安装，不要声称使用了原字体。选择指标接近、可稳定导出的替代字体，并通过字号和行高校准。

## 三、重建

1. 用语义 HTML 建立 `header/main/section/article`，先还原信息结构。
2. 用 CSS Grid/Flex 构建布局；只有 PDF 本身是自由定位且普通流难以表达时，才局部绝对定位。
3. 使用 `mm` 和 `pt` 重建 A4、页边距和字体。
4. 对固定两页模板显式建立两个 `.resume-page`，避免浏览器自动分页漂移。
5. 图片保留原始比例；测量 PDF 实际边界，而非根据“证件照”猜尺寸。
6. 文本内容放在 JSON 或结构化数据中，模板只负责渲染。
7. 实现屏幕画布与打印样式，打印时移除阴影和页间隙。

## 四、内容与表现分离

视觉还原完成后，保持内容数据、结构模板和样式分离。浏览器页面只呈现简历正文，不加入编辑工具栏或其他管理界面；文本、列表、链接和照片修改均通过结构化内容源完成，再重新构建 HTML。

## 五、对照验收

至少完成三轮：

### 1. 结构对照

确认页数、模块顺序、列结构、分页和图片存在。

### 2. 度量对照

使用文本/图片坐标或视觉测量比较：

- 页面尺寸和页边距；
- 主要字号分布；
- 姓名、一级标题、项目标题的纵向坐标；
- 照片 `x0/top/x1/bottom`；
- 每页最后一行位置和底部留白。

### 3. 逐页视觉对照

并排查看参考页和生成页，检查字体观感、换行、列表缩进、线条、照片裁切、模块密度和整体重心。差异来自字体替代时，优先修正字面大小、字重、行高和列宽，不用大量单点偏移掩盖问题。

完成后再加入微小审美优化。用户要求复刻时，任何优化不得明显改变原风格。

## 六、常见失败

- 直接把整页 PNG 当背景，导致文字不可搜索和编辑；
- 只读文本，不渲染页面；
- 用 DOCX 预览代替 PDF 视觉；
- 使用 `cover` 裁切照片却不检查头顶；
- 根据 CSS 声明猜字体，未检查生成 PDF 实际嵌入字体；
- 只看浏览器，不查看导出的 PDF；
- 为像素对齐硬编码大量坐标，内容一改即失效；
- 把参考简历中的个人数据留在公共模板。
